# Surface RT display appliance

The Surface boots, through the usual APX + RAM U-Boot step, into a small read-only OS. That OS runs only SSH, Xorg (OpenTegra) and the display receiver, which the PC starts over SSH. The kernel includes the tegra_vde cache-sync patch. Nura on p2 is never touched and stays bootable from its own extlinux label.

## Decisions

| Area | Choice | Why |
|---|---|---|
| Userspace source | Alpine edge armv7 binary APKs, version-locked in `packages.lock`. The `.apk` files are archived under `cache/apks/` and checked by sha256. | GStreamer 1.28.7 is the exact version proven on this device; v3.24 ships 1.28.3. Rebuilding userspace from source would add work without changing what boots. |
| Init | OpenRC + eudev, Alpine's default | The packages are built for it. No logind, no session manager. The receiver needs neither. |
| Rootfs | `rootfs.squashfs` on p1 (FAT), under a tmpfs overlay | The appliance never mounts p2, so Nura stays byte-identical. Every path is writable in RAM and nothing persists by accident. |
| Kernel | Pinned tarball `bfffc6d` plus the patch. Config identical to the running kernel. VDE stays `=m`, enabled with `tegra_vde.skip_capture_cache_sync=1` on the cmdline. | The smallest delta from the proven kernel. In-tree modules are signed by the same build, so there is no taint. |
| Identity | The existing SSH host keys and `authorized_keys` are copied once into `p1:/appliance/identity/` by the user-run installer. | The pinned host key keeps working. The appliance never generates keys. |
| Boot selection | Each release gets its own extlinux label. `surface-boot-select` is the only writer of `DEFAULT`. It is run via sudo on Nura, or via doas on the appliance. | Fallback works over SSH while Linux is up, and over UMS (U-Boot Volume Down menu) when it is not. |
| Sender | Unchanged | It already passes `DISPLAY=:0 XDG_RUNTIME_DIR=/run/user/10000` and the receiver path. |

## Layout

```text
PC: appliance/
  build.sh               one entry point: kernel → rootfs → initramfs → release
  build-kernel.sh        pinned tarball + patch → out/kernel/{zImage,dtb,kernel.release,config,modules/}
  build-rootfs.sh        Docker alpine:edge, apk --arch armv7 --root, proot+qemu-arm for scripts → out/rootfs.squashfs
  build-initramfs.sh     busybox-static + storage modules + init → out/initramfs
  packages.txt           world list (hand-edited)
  packages.lock          name version sha256 (generated by lock.sh, reviewed)
  overlay/               files copied into the rootfs (OpenRC services, sshd_config, xorg.conf, doas rule)
  install/               surface-install.sh (stage) and surface-boot-select (DEFAULT writer), both run as root on the device

Release: ~/surface-releases/<id>/
  zImage  initramfs  tegra30-microsoft-surface-rt.dtb  rootfs.squashfs  manifest.json  SHA256SUMS

Device p1 (FAT, 17C0-8631):
  /vmlinuz /initramfs /dtbs/...          Nura, untouched
  /extlinux/extlinux.conf                Nura label + one label per release
  /appliance/<id>/...                    release files
  /appliance/identity/                   ssh_host_*_key{,.pub}, authorized_keys
  /appliance/recovery/extlinux.conf.orig original config, byte-exact
```

## Units

Riskiest first. Each unit ends in a check.

1. **Kernel lever.**
   - Check: the effective config is identical to the running config, and the patch applies with no fuzz.
   - Check: module `.text` matches stock except tegra-vde and 3 known modules.
2. **Rootfs lever.**
   - Check: under qemu, `python3 -c 'import gi; Gst...'` loads.
   - Check: `gst-inspect-1.0 v4l2slh264dec` is present, and `Xorg -version` runs.
   - Check: the package versions equal the lock.
3. **Initramfs and release bundle.**
   - Check: the cpio contents include every needed module for `kernel.release`.
   - Check: the init script passes `sh -n`, and the manifest hashes verify.
4. **Stage (user sudo on Nura).**
   - Steps: the release goes to `p1:/appliance/<id>`, the label is added, and the identity is captured. DEFAULT stays `surface-rt`.
   - Check: the bundle `sha256sum -c` passes before any sudo, and the Nura boot files hash the same before and after.
5. **Recovery rehearsal, then select (user, APX).**
   - UMS (`ums 0 mmc 0`) exposes the whole eMMC to the PC writable. Only p1 is touched, through `recovery-pc.sh`, which mounts it with udisks (no sudo).
   - Steps: APX → Volume Down → bootmenu → "mount internal storage". On the PC, run `recovery-pc.sh status`, then `recovery-pc.sh select <id>`. This exercises the same write path as `restore`. Exit UMS, then "boot Linux from internal storage".
   - If any of those steps fails, nothing has changed: DEFAULT is still Nura.
   - Also note whether the extlinux menu responds to the buttons.
6. **Boot the appliance.**
   - Check: `verify-boot.sh <id>`, i.e. the cmdline, `skip_capture_cache_sync=Y`, `tainted=0`, the root is overlay, p2 is not mounted, and no desktop processes are running.
   - Check: the pinned host key is accepted.
   - If it fails: APX → UMS → `recovery-pc.sh restore` → Nura.
7. **Stream gates.**
   - Production `surface-display.service` works unchanged.
   - Checksum equals stock, replay ×5 (decoder p50 ≤ 20.5 ms), and live cadence matches or beats the Nura result.
8. **Durability.**
   - A second APX boot passes the unit 6 checks without any manual step.
   - `surface-boot-select nura` brings Nura back.
